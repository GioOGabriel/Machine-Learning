📊 INTERPRETAR OS RESULTADOS
=============================

TABELA DE RESULTADOS (CSV)
---------------------------
Colunas:
- Algoritmo: Nome do modelo
- Acurácia: Porcentagem de previsões corretas (0.00-1.00)
- Precisão: De quantas previsões positivas, quantas estão corretas
- Recall: De quantas amostras positivas, quantas foram detectadas
- F1-Score: Média harmônica entre Precisão e Recall [MÉTRICA PRINCIPAL]
- AUC-ROC: Capacidade de discriminação entre classes
- Tempo (s): Tempo de treinamento em segundos

INTERPRETAR VALORES:
- Mais próximo de 1.0 = Melhor desempenho
- Random Forest: 0.9080 F1-Score = 90.80% de desempenho geral

GRÁFICOS EXPLICADOS:
- Comparação de Métricas: 4 barras para cada métrica
- Ranking F1-Score: Barras horizontais, o maior está no topo
- Curvas ROC: Quanto mais ao canto superior esquerdo, melhor
- Heatmap: Verde=melhoria, Vermelho=piora, Branco=sem mudança
- Tempo: Barras vermelhas mais curtas = mais rápido

📈 MÉTRICAS EXPLICADAS
=======================

Acurácia (Accuracy)
  - O que: Porcentagem total de previsões corretas
  - Fórmula: (TP + TN) / Total
  - Intervalo: 0% a 100%
  - Quando usar: Problemas balanceados

Precisão (Precision)
  - O que: De quantas previsões de "Alzheimer", quantas estão corretas
  - Fórmula: TP / (TP + FP)
  - Importa: Evitar alarmes falsos desnecessários
  - Alto quando: Poucos falsos positivos

Recall (Sensibilidade / Sensitivity)
  - O que: De quantos casos reais de Alzheimer, quantos foram detectados
  - Fórmula: TP / (TP + FN)
  - CRÍTICO: Não deixar passar casos reais
  - Alto quando: Detecta a maioria dos casos positivos

F1-Score ⭐ PRINCIPAL
  - O que: Média harmônica entre Precisão e Recall
  - Fórmula: 2 × (Precisão × Recall) / (Precisão + Recall)
  - Vantagem: Balanceia ambas as métricas
  - Intervalo: 0.0 a 1.0
  - Este projeto: MÉTRICA DE DECISÃO

AUC-ROC (Area Under Curve - Receiver Operating Characteristic)
  - O que: Capacidade de discriminação entre as duas classes
  - Intervalo: 0.5 (aleatório) a 1.0 (perfeito)
  - Alto quando: Bom em separar Saudável vs Alzheimer
  - Este projeto: Métrica complementar

Tempo de Treinamento
  - O que: Quantos segundos leva para treinar o modelo
  - Importa: Para sistemas em tempo real
  - Random Forest: 0.60s (aceitável)
  - KNN: 0.0007s (extremamente rápido)


🔬 ALGORITMOS EXPLICADOS
=========================

1. RANDOM FOREST 🥇 (Melhor Desempenho)
   └─ O que: Ensemble de árvores aleatórias
   └─ Força: Acurácia (91.22%), Precisão (95.25%)
   └─ Fraqueza: Menos interpretável
   └─ Quando usar: Produção clínica

2. SUPPORT VECTOR MACHINE (SVM)
   └─ O que: Encontra hiperplano que maximiza margem
   └─ Força: AUC-ROC (0.9362), robustez
   └─ Fraqueza: Tempo computacional maior (1.51s)
   └─ Quando usar: Precisa de confiabilidade

3. DECISION TREE 📚 (Melhor Melhoria)
   └─ O que: Árvore de decisão com nós e folhas
   └─ Força: Interpretabilidade, melhoria (+3.29%)
   └─ Fraqueza: Menor acurácia (86.04%)
   └─ Quando usar: Precisa explicar ao paciente

4. MULTI-LAYER PERCEPTRON (MLP)
   └─ O que: Rede neural artificial
   └─ Força: Desempenho decente, velocidade (-70%)
   └─ Fraqueza: Menos estável, precisa mais ajuste
   └─ Quando usar: Experimentação

5. LOGISTIC REGRESSION
   └─ O que: Regressão logística simples
   └─ Força: Velocidade (5ms), simplicidade
   └─ Fraqueza: Performance modesta (83.06%)
   └─ Quando usar: Baseline, referência

6. K-NEAREST NEIGHBORS (KNN) ⚡ (Mais Rápido)
   └─ O que: Classifica por vizinhos mais próximos
   └─ Força: Extremamente rápido (0.7ms), alto recall
   └─ Fraqueza: Menor acurácia (72.37%)
   └─ Quando usar: Screening em tempo real

🐛 RESOLUÇÃO DE PROBLEMAS
==========================

PROBLEMA: ModuleNotFoundError
SOLUÇÃO: pip install matplotlib seaborn

PROBLEMA: "Dataset não encontrado"
SOLUÇÃO: Coloque em "data/alzheimers_disease_data.csv"
        Ou selecione via diálogo quando executar

PROBLEMA: Muito lento
SOLUÇÃO: Reduzir cv de 5 para 3 em GridSearchCV
        Reduzir número de parâmetros no grid
        Use apenas alguns algoritmos

PROBLEMA: Erro de memória (RAM)
SOLUÇÃO: Use -n_jobs=-1 para paralelização (já está)
        Reduza tamanho do grid
        Processe em chunks
